# Native agent transport contract

The core protocol exports `AgentAdapter` with `name`, `capabilities`, `detect(projectRoot)` and `sendReview(session, comments)`. `polling` indicates an MCP fallback; `liveDelivery` indicates an active session can receive pushed reviews. Browser clients only see Pointback events and do not know the agent harness.

The first implementation is an in-process Pi extension (`packages/adapters/pi`). It pairs with the daemon using the canonical project-root ID and token. On Pi `session_start` it opens `/events?project=…&token=…&role=agent&session=<Pi session ID>`; on shutdown it closes the socket. The daemon advertises `agent.connected`/`agent.disconnected` and exposes `/agents` for late-joining browsers. When it receives `review.submitted` (or `comment.reopened`), the extension retrieves comments and sends a follow-up message to Pi; after delivery it acknowledges them. It also replays open submitted comments on reconnect. Screenshots and comment resolution are exposed as Pi tools. Pi-specific APIs remain inside that adapter; core session/comment wire shapes are shared with MCP.

A future Codex/Claude/OpenCode transport can implement the same adapter interface and register its active session without changing the browser. Agents without live delivery use the generic MCP server. Codex's app-server supports turn submission when Pointback owns that connection, but attaching reliably to an unrelated active CLI/Desktop-owned session is not yet a supported path; do not claim native Codex push delivery until this can be tested against the owning session.
