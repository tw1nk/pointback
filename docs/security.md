# Local security contract (prototype)

The daemon listens only on `127.0.0.1` (port `47832` unless `POINTBACK_PORT` is set). Storage defaults to `~/.local/share/pointback` (`POINTBACK_DATA_DIR` overrides). On first use it creates a 32-byte secret with mode `0600` in a `0700` directory. Each project ID is `project_` followed by the first 24 hex characters of SHA-256 of its canonical realpath. Its token is HMAC-SHA256(project ID, local secret). The Vite plugin derives the token from its project root and injects it only in dev HTML; MCP derives it from the agent working directory. Requests include `x-pointback-project` and `x-pointback-token`. WebSocket connections use matching URL query parameters. Never expose Vite to untrusted users: clients that can read its injected page can obtain its token.

HTTP origins other than localhost/127.0.0.1 are rejected; the token prevents access from other local projects. This is a local development mechanism, **not** an authentication boundary against other processes running as the same OS user. Tokens in WebSocket URLs may appear in local diagnostic logs; don't publish them. Screenshot and comment APIs require a matching project token, and references to sessions/images are checked against that project.

Browser DOM metadata redacts `data-pointback-private`, hidden elements, input controls, and Pointback UI. Screenshot rendering excludes these nodes and paints private regions black. Screenshot privacy has not yet been audited across frameworks, CSS effects, canvas, iframes, or all browsers; do not use it on sensitive production data. The prototype does not capture cookies, request headers, or input values intentionally.
